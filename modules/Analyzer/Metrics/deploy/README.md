# Metrics Module — Build, Test, and Run Guide

A network protocol stack metrics collection service based on Go + cilium/ebpf. It uses 11 kernel probes (tp_btf / fentry) to aggregate PPS, cross-layer latency, and packet loss rate in the kernel space, which are polled every second and pushed to the frontend via WebSocket.

## Project Structure

```
modules/Analyzer/Metrics/
├── bpf/                          # eBPF C source code
│   ├── metrics.c                 # Compilation entry point (includes the following three files)
│   ├── common.h                  # Shared structures, Map definitions, auxiliary functions
│   ├── rx.h                      # RX probes (link/network/transport)
│   ├── tx.h                      # TX probes (link/network/transport)
│   └── drop.h                    # Packet drop probes
├── cmd/metrics/main.go           # Program entry point
├── pkg/
│   ├── aggregation/              # Aggregation engine (Collector, BuildMessage)
│   ├── bpf_engine/               # BPF loader + Map read/write interfaces
│   │   └── ebpf/                 # Files generated by bpf2go (isolated directory)
│   └── server/                   # WebSocket server
├── test/                         # All test files
├── deploy/                       # Deployment scripts and this document
└── Dockerfile                    # Multi-stage build image
```

## Prerequisites

| Dependency | Version Requirement | Purpose |
|------|---------|------|
| Go | >= 1.22 | Compilation |
| Clang + LLVM | >= 15 | Compile BPF C code |
| libbpf-dev (or kernel BTF) | Kernel >= 5.8 | CO-RE support |
| Linux Kernel | >= 5.8, BTF enabled | tp_btf / fentry probes |

Check if the kernel supports BTF:
```bash
ls /sys/kernel/btf/vmlinux  # If it exists, BTF is supported
```

## Compilation

### 1. Generate BPF Go Bindings
```bash
cd modules/Analyzer/Metrics
go generate ./pkg/bpf_engine/ebpf/
```

### 2. Compile Go Binary
```bash
go build -o bin/metrics ./cmd/metrics
```

### One-step Compilation
```bash
go generate ./pkg/bpf_engine/ebpf/ && go build -o bin/metrics ./cmd/metrics
```

## Testing

### Unit Tests (no root required)
```bash
go test -v ./test/
```

Currently covers 35 test cases:
- Aggregation slot encoding/decoding (AggIdx / DecodeSlot round trip)
- SumPerCPU accumulation (Multi-CPU / All zeros / Single CPU)
- BuildMessage output (PPS/LAT/DROP three types of message formats, RX address reversal, direction names)
- WebSocket parameter parsing (IPv4/IPv6/ICMP, port boundaries, illegal inputs, unknown types)
- WebSocket push stream (26 aggregated messages, nested JSON string format, 1-second timeout)
- Collector integration (Empty data heartbeat, PPS/LAT calculation with data)
- High PPS scenario (Large value correctness)

### BPF Integration Tests (requires root)
```bash
sudo -E go test -v -run TestBPFEngine -count=1 ./test/
```

This test will actually load the BPF bytecode and attach all 11 probes to the kernel, verifying:
- BPF ELF loaded successfully
- All tp_btf / fentry probes attached successfully
- Resources released correctly

### All Tests (requires root)
```bash
sudo -E go test -v -count=1 ./test/
```

## Running

### Run Locally

```bash
# Requires root privileges to attach eBPF probes
sudo -E ./bin/metrics
```

After starting up, the service listens on `ws://0.0.0.0:8020/ws`.

### Use Deployment Script
```bash
sudo -E ./deploy/start.sh
```

### Run via Docker
```bash
docker build -t metrics .
docker run --privileged --net=host metrics
```

## WebSocket Interaction Validation

### 1. Install websocat
```bash
# Ubuntu/Debian:
wget -qO websocat https://github.com/vi/websocat/releases/download/v1.11.0/websocat.x86_64-unknown-linux-musl
chmod +x websocat && sudo mv websocat /usr/local/bin/
```

### 2. Connect and Send Filter Rules

Terminal A — Start the service:
```bash
sudo -E ./bin/metrics
```

Terminal B — Connect to WebSocket:
```bash
websocat ws://localhost:8020/ws
```

Send IPv4 TCP filtering command:
```json
{"type":"NumLatencyFrequency","params":{"ipv4_flag":"true","ipv6_flag":"false","sip":"","dip":"","sport":0,"dport":0,"protocol":"tcp"}}
```

### 3. Generate Traffic and Observe Output

Terminal C — Generate network traffic:
```bash
curl -s https://example.com > /dev/null
# Or
ping -c 5 8.8.8.8
```

Terminal B will receive 26 aggregated messages every second, format examples:

**PPS Messages** (one for each layer, direction, and protocol, totally 12):
```json
{"type":"NumLatencyFrequency","data":"{\"layer\":\"link\",\"direction\":\"receive\",\"type\":\"ipv4\",\"pid\":0,\"saddr\":\"8.8.8.8\",\"daddr\":\"192.168.1.100\",\"sport\":0,\"dport\":0,\"num\":150,\"pps(s)\":150}"}
```

**Latency Messages** (cross-layer combinations × direction × protocol, totally 12):
```json
{"type":"NumLatencyFrequency","data":"{\"crosslayer\":\"linknetwork\",\"direction\":\"send\",\"type\":\"ipv4\",\"pid\":0,\"pid_name\":\"curl\",\"saddr\":\"192.168.1.100\",\"daddr\":\"93.184.216.34\",\"sport\":43210,\"dport\":443,\"LAT(ms)\":0.125,\"frequency(s)\":100}"}
```

**Drop Messages** (one per protocol, totally 2):
```json
{"type":"NumLatencyFrequency","data":"{\"type\":\"ipv4\",\"pid\":0,\"saddr\":\"\",\"daddr\":\"\",\"sport\":0,\"dport\":0,\"drop(s)\":2}"}
```

### 4. Switch Filtering Conditions

Sending new commands will **automatically cancel** the old monitoring task and start a new one:
```json
{"type":"NumLatencyFrequency","params":{"ipv4_flag":"false","ipv6_flag":"true","sip":"","dip":"","sport":0,"dport":0,"protocol":"udp"}}
```

## Kernel Probes List

| # | Layer | Direction | Attach Type | Kernel Function |
|---|-------|-----------|-------------|-----------------|
| 1 | Link | RX | tp_btf | netif_receive_skb |
| 2 | Network | RX (v4) | fentry | ip_local_deliver |
| 3 | Network | RX (v6) | fentry | ip6_input |
| 4 | Transport | RX (v4) | fentry | inet_recvmsg |
| 5 | Transport | RX (v6) | fentry | inet6_recvmsg |
| 6 | Transport | TX (v4) | fentry | inet_sendmsg |
| 7 | Transport | TX (v6) | fentry | inet6_sendmsg |
| 8 | Network | TX (v4) | fentry | ip_finish_output |
| 9 | Network | TX (v6) | fentry | ip6_finish_output |
| 10 | Link | TX | tp_btf | net_dev_start_xmit |
| 11 | Drop | — | tp_btf | kfree_skb |

## Troubleshooting

```bash
# Check if BTF is available
ls /sys/kernel/btf/vmlinux

# Check available tracepoints
sudo cat /sys/kernel/debug/tracing/available_events | grep -E "^(net|skb):"

# View loaded BPF programs
sudo bpftool prog list | grep metrics

# View BPF Maps
sudo bpftool map list | grep -E "agg_map|five_tuple"
```
