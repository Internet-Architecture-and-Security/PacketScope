# PacketScope Metrics

A kernel-space network metrics collection module based on **Go + cilium/ebpf**. It aggregates data in kernel space in real-time using 11 eBPF probes (fentry / kprobe / tracepoint), reads them periodically every second, and pushes them to the frontend via **WebSocket**. It supports running across various Linux kernel versions (5.10 LTS ~ 6.12 LTS).

## Architecture Overview

```
Kernel Space                                User Space
┌────────────────────────────────┐          ┌───────────────────────────────┐
│  eBPF Probes (11 total)        │          │  Go Service                   │
│                                │          │                               │
│  RX fentry (3 layers)          │          │  Ticker(1s)                   │
│  TX fentry (3 layers)     ───▶ │ PERCPU   │  ├─ Read agg_map (26 slots)   │
│  Drop (kprobe/tracepoint)      │  ARRAY   │  ├─ SumPerCPU + Calc metrics  │
│                                │  agg_map │  └─ WebSocket push JSON       │
│                                │          │                               │
│  5-Tuple Filter Map            │          │  ws://0.0.0.0:8020/ws         │
└────────────────────────────────┘          └───────────────────────────────┘
```

**Design Highlight**: Whether the traffic PPS is 1 or 1,000,000, the user space performs exactly 52 Map operations per second with $O(1)$ overhead, which will not degrade as traffic increases.

## System Requirements

| Requirement | Minimum Version | Description |
|------|---------|------|
| Linux Kernel | **5.10 LTS** | Needs BTF enabled; fentry introduced in 5.5 |
| Go | >= 1.22 | For compilation |
| Clang + LLVM | >= 15 | Compile eBPF C source code |
| root privileges | — | `CAP_BPF` required to load BPF programs |

Check kernel BTF support:
```bash
ls /sys/kernel/btf/vmlinux   # If it exists, BTF is available
```

## Quick Start

### 1. Compile

```bash
cd modules/Analyzer/Metrics

# One-click compile (Generates BPF bindings + Go binary → bin/metrics)
./build.sh
```

### 2. Run

```bash
# root privileges required to attach eBPF probes
sudo -E ./build.sh run

# Or run the binary directly
sudo -E ./bin/metrics
```

After startup, the service listens on `ws://0.0.0.0:8020` (frontend address) and `ws://0.0.0.0:8020/ws` (both are valid).

### 3. Test

```bash
# Download necessary dependencies
./test.sh setup

# Unit tests (no root required)
./test.sh

# Cross-kernel compatibility tests (requires root + QEMU)
sudo -E ./test.sh vmtest
```

### 4. Docker Deployment

```bash
# Build and run
./build.sh docker build
./build.sh docker run

# Or one-step execute
docker build -t packetscope/metrics .
docker run --privileged --net=host packetscope/metrics
```

## Script Details

### `build.sh` — Build & Deploy

```
Usage: ./build.sh [command]

  build          Compile (Generate BPF bindings + Go binary)   [default]
  run            Compile and start the service as root
  docker build   Build Docker image
  docker run     Start Docker container (auto-builds image)
  clean          Remove bin/metrics and bpf/out/
  help           Show help

Environment Variables:
  OUTPUT=bin/metrics                 Output path
  IMAGE=packetscope/metrics:latest   Docker image name
```

### `test.sh` — Test Suite

```
Usage: ./test.sh [command]

  unit          Unit tests (no root required)               [default]
  integration   BPF integration tests (requires root)
  vmtest        Cross-kernel QEMU compat tests (requires root)
                  ./test.sh vmtest 5.15 6.6           # Specific versions
  all           Run all tests
  setup         Install dependencies + fetch kernel images
  help          Show help

Environment Variables:
  KERNELS="5.10 5.15 6.1 6.6 6.12"  Kernels for vmtest
  TIMEOUT=180                       Timeout per VM in seconds
  VERBOSE=1                         Verbose output
```

### `scripts/build-ebpf.sh` — Standalone BPF Object Build

```bash
./scripts/build-ebpf.sh                    # Compile bpf/out/metrics_bpf.o
TARGET_ARCH=arm64 ./scripts/build-ebpf.sh  # Cross-compile
```

### `deploy/start.sh` — Minimal Startup

```bash
sudo -E ./deploy/start.sh   # Auto-check/build binary then run
```

### `test/kernel-compat/vmtest/` — vmtest Core Scripts

```bash
# Fetch kernel images (>= 5.10, from ghcr.io/cilium/ci-kernels)
./test/kernel-compat/vmtest/fetch-kernels.sh
./test/kernel-compat/vmtest/fetch-kernels.sh 5.15 6.6  # Specific versions

# Build initramfs (contains test binaries + metrics service)
./test/kernel-compat/vmtest/mkrootfs.sh

# Boot QEMU and run tests
sudo -E ./test/kernel-compat/vmtest/run-vmtest.sh
sudo -E ./test/kernel-compat/vmtest/run-vmtest.sh 5.15 6.6  # Specific versions
```

## WebSocket Protocol

Connection Address: `ws://<host>:8020/ws`

**Send Filter Rules:**
```json
{
  "ipv4_flag": "true",
  "sip": "192.168.1.100",
  "dip": "10.0.0.1",
  "sport": 0,
  "dport": 80,
  "protocol": 6
}
```
> Numeric fields set to `0` mean wildcard (match any).

**Receive Message Format:**

First message is ACK:
```json
{"type": "NumLatencyFrequency", "status": "started"}
```

Subsequent messages are periodic metrics (`data` is a nested JSON string):
```json
{
  "type": "NumLatencyFrequency",
  "data": "{\"layer\":\"network\",\"direction\":\"receive\",\"type\":\"ipv4\",\"num\":1234,\"pps(s)\":1234,\"drop(s)\":0,\"LAT(ms)\":0.5}"
}
```
